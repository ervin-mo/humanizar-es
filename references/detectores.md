## 1. Principio

**Ningún detector individual es concluyente.** En el benchmark, la misma variante
recibió:

- ZeroGPT: «Your Text is Human written», **6.7%**
- GPTZero: «We are highly confident this text was AI generated», **0% humano**

Los dos detectores son contradictorios sobre el mismo texto exacto. Esto no es un bug
de la medición: es lo que documenta la literatura de validación cruzada, y es la razón
por la que las variantes hay que medirlas en varios instrumentos y reportar **cuál**
dijo qué.

Corolario práctico: si el usuario pregunta «¿ya no lo detecta?», la respuesta honesta
nunca es sí o no. Es «bajó de X a Y en el detector Z; en el detector W sigue marcado».

## 2. Controles humanos

**Siempre mide al menos un texto humano conocido junto con el texto a humanizar.** Sin
control no puedes interpretar el score: no sabes si un 40% significa «muy IA» o «así
puntúa el español formal en este detector».

Los dos controles usados en el benchmark, ambos en `ejemplos/controles/`:

### Control A — Quijote (1605)

Formal pero arcaico. Sirve para verificar que el instrumento distingue humano de
máquina en español.

| Detector | Resultado |
|---|---|
| ZeroGPT | 23.7% — «Most Likely Human written» |
| GPTZero | «entirely human», 99% humano (en la primera corrida; luego cambió, ver §4) |
| Perplejidad / burstiness locales | 28.50 / 58.23 |

### Control B — Wikipedia «Metafísica», revisión de dic-2014

**Este es el control importante.** Prosa académica en español moderno, escrita por
humanos, anterior a los LLM, y del mismo tema que el texto del benchmark. Es el
control comparable.

| Detector | Resultado |
|---|---|
| ZeroGPT | **46.5%** — «Your Text contains mixed signals» |
| GPTZero | **100% IA** — falso positivo (misma corrida en la que el Quijote salió humano) |
| Perplejidad / burstiness locales | **10.35 / 16.24** — más previsible que el ensayo generado (12.33) |
| Clasificador local XLM-R | **99.96% IA** — falso positivo |

Cómo obtener controles así:

```bash
# Revisión antigua de Wikipedia (pre-LLM), vía API
curl -s "https://es.wikipedia.org/w/api.php?action=query&prop=revisions&titles=Metaf%C3%ADsica&rvlimit=1&rvprop=content|ids|timestamp&rvstart=2015-01-01T00:00:00Z&rvdir=older&format=json&formatversion=2"
```

Clave: usar `rvstart` anterior a 2022 para garantizar que es humano. Si publicas el
extracto, respeta su licencia (CC BY-SA): ver `ejemplos/controles/LEEME.md`.

**Conclusión que saca el control B:** GPTZero y el clasificador local marcan como IA
prosa académica en español escrita por humanos, y ZeroGPT la deja a medio camino. Por eso su veredicto sobre textos humanizados de registro
académico **no aporta información**. Si no hubiéramos medido el control, habríamos
concluido falsamente que las tres variantes fracasaron.

## 3. ZeroGPT

### Estado

Funciona sin cuenta, acepta hasta 15,000 caracteres, soporta español. **Es el
instrumento más útil de los tres.**

### Automatización

`scripts/score-zerogpt.sh`. Flujo que funciona:

1. `goto https://www.zerogpt.com/`
2. `focus` al `textarea[name="textArea"]` y `keyboard.paste(texto)`
3. **Eliminar overlays de anuncios** (crítico, ver trampa)
4. Localizar el botón por texto (`Detect Text`), `scrollIntoView`, obtener su
   rectángulo y hacer **clic por coordenadas** con `mouse.click`
5. Esperar a que aparezca `/Your Text is/` en el cuerpo

### Trampa principal: los anuncios interceptan los clics

ZeroGPT sirve un interstitial de Google (`#google_vignette`). El clic cae en el
anuncio, la URL cambia a `zerogpt.com/#google_vignette` y **el escaneo nunca arranca**,
sin mensaje de error. Hay que quitarlos antes del clic:

```js
await page.evaluate(() => {
  const sels = 'iframe[id*="google_ads"], ins.adsbygoogle, div[id*="google_vignette"], ' +
               'div[id*="aswift"], iframe[id*="aswift"]';
  document.querySelectorAll(sels).forEach((e) => e.remove());
});
```

### Formato de salida

```
Your Text is <veredicto>
<porcentaje>%    AI GPT*
```

Veredictos observados, en orden:

| Veredicto | Rango de % observado |
|---|---|
| «Your Text is Human written» | 6.7% – 7.7% |
| «Most Likely Human written, may include parts generated by AI/GPT» | 23.7% |
| «contains mixed signals, with some parts generated by AI/GPT» | 46.5% |
| «Your Text is AI/GPT Generated» | 81.2% – 98.5% |

### Cuidado al parsear

La página tiene otros porcentajes que **no** son el score: `98.4%` y `<1%` son
estadísticas de marketing («tech-stat-value»), y `30%` es el descuento promocional.
El score real es el **primer** porcentaje, justo debajo del veredicto. Nunca tomes el
primer `\d+%` del `innerText` completo sin anclar al bloque de resultado.

### Reproducibilidad

El Quijote se midió dos veces en corridas separadas: 23.7% las dos veces. El
instrumento es estable.

## 4. GPTZero

### Estado

Funciona sin cuenta. **Declara soporte de español en su propia página:** «Admitimos
detección de IA en Español con un 99% de precisión».

### Automatización

`scripts/score-gptzero.sh`. Flujo distinto al de ZeroGPT:

1. `goto https://gptzero.me/`
2. Pegar en el `textarea` (no tiene `name`, es el único visible)
3. Eliminar overlays de anuncios
4. Botón con texto exacto **`Scan`** (no «Detect»). Clic por coordenadas
5. **El escaneo abre una página nueva** en `https://app.gptzero.me/`

El punto 5 es la trampa: el resultado no aparece en `p1`. Hay que esperar una página
nueva en el espacio de tareas y leerla:

```js
let result = null;
for (let i = 0; i < 60; i++) {
  await page.waitForTimeout(2000);
  const ps = (await task.pages()).filter((p) => p.label !== "p1");
  if (ps.length) { result = ps[ps.length - 1]; break; }
}
```

Y cerrar esa página antes de la siguiente medición, o las corridas se contaminan.

### Formato de salida

Veredictos observados:

- `We are highly confident this text was AI generated` + `Human 0%`
- `We are highly confident this text is entirely human` + `Human 99%`

Cuidado: los `30%` que aparecen en la página son el descuento de una promoción
(«Back to school 30% off»), no parte del resultado.

### Limitaciones demostradas

**1. Marca como 100% IA un artículo de Wikipedia en español de 2014 escrito por
humanos.** No lo uses como criterio único para registro académico o enciclopédico.

**2. No es reproducible.** El mismo archivo del Quijote dio resultados opuestos en dos
momentos de la misma sesión de trabajo:

| Momento | Veredicto sobre el Quijote (mismo archivo) |
|---|---|
| Primera medición | «entirely human», **99% humano** |
| Mediciones posteriores (dos corridas) | «AI generated», **0% humano** |

Se verificó que el resultado leído correspondía al texto enviado (el script comprueba
que la página de resultados contenga una huella del archivo), así que no es un error de
lectura: es el detector cambiando de opinión sobre un texto idéntico.

**3. Llega a devolver un veredicto constante.** En el estado degradado marcó como
«AI generated» un texto inequívocamente humano y coloquial: una anécdota personal breve
(583 caracteres) escrita a mano. Si **todo** lo que le pases sale
«AI generated», el instrumento dejó de medir — probablemente agotó la cuota gratuita y
devuelve un valor por defecto.

### Consecuencia operativa

Usa GPTZero solo como señal secundaria y **siempre con un control humano en la misma
corrida**. Si el control humano también sale marcado como IA, **descarta la corrida
entera**: no reportes el número. Un instrumento que marca todo no mide nada.

## 5. Grammarly

### Estado

Es el detector con el que se detectó el problema del texto de prueba. **Se pudo usar
una vez y luego dejó de responder.**

### Lo que se logró

Se reprodujo exactamente el resultado de partida sobre el texto original:
**«100% of this text appears to be AI-generated»**. Eso valida el punto de partida del
benchmark.

### Trampa: bloqueo tras los escaneos gratuitos

Después del primer escaneo, el botón `Scan for AI` dejó de disparar el escaneo. Se
intentó, sin éxito:

- `page.click(ref)` → `<div> intercepts pointer events`
- `page.click("text=Scan for AI")` → «element is not visible in the viewport»
- `loc=role:button[name="Scan for AI"]` → «matched 0 elements»
- `mouse.click` en el centro y en el borde del botón
- Eventos crudos por CDP (`Input.dispatchMouseEvent`)
- Secuencia completa de `pointerdown`/`mousedown`/`pointerup`/`mouseup`/`click` por JS

Se verificó que **no había overlays ni diálogos**: `document.elementFromPoint` en el
botón devolvía su propio `<span>`, y no existía ningún elemento fijo con z-index
cubriendo la pantalla. El contador de palabras sí registraba el texto
(«757/1,400 words»), o sea que el pegado funcionaba y lo que fallaba era el arranque
del escaneo.

Conclusión: es límite de escaneos gratuitos por IP, no un problema de automatización.

### Cómo cerrar esta verificación

Iniciar sesión en Grammarly dentro del navegador de ego-browser.
Con sesión iniciada los escaneos son ilimitados. Después:

```bash
./scripts/score-grammarly.sh texto.txt
```

El selector del botón es `button.gds-button-primary`, el `textarea` es
`textarea[name="toolInput"]`, y el resultado aparece como
`N% of this text appears to be AI-generated`.

### Trampa al esperar el resultado

El estado inicial de la página ya contiene la cadena
«—% of this text appears to be AI-generated». Una condición de espera como
`/of this text appears to be AI-generated/` se cumple **de inmediato** con el
placeholder y devuelve `—%` como si fuera un resultado. Hay que exigir dígitos y
ausencia del em-dash:

```js
return /[0-9]+% of this text appears to be AI-generated/.test(t) && !/—%/.test(t);
```

## 6. Instrumento local

### Instalación

```bash
python3 -m venv .venv
.venv/bin/pip install -r scripts/requirements.txt
```

La primera corrida descarga `Qwen/Qwen2.5-0.5B` (~1 GB) a `~/.cache/huggingface`.
Funciona en CPU y sin conexión después de la descarga. Seis textos de ~800 palabras
tardan unos 30 segundos en un portátil.

### Qué mide

`scripts/detect_local.py`:

1. **Perplejidad global** — qué tan previsible es el texto para el modelo.
2. **Burstiness** — desviación de la perplejidad entre oraciones (solo oraciones de 5
   palabras o más: en una más corta la perplejidad es ruido).
3. **Longitud de oración** — media y desviación. `scripts/estilo.py` da lo mismo y más
   sin instalar nada.

| Texto | Perplejidad | Burstiness |
|---|---|---|
| 00 original (IA) | 12.33 | 10.19 |
| 01 reglas de estilo | 16.50 | 38.94 |
| 02 cadena de traducción | 11.79 | 12.45 |
| 03 adversarial | 17.54 | 68.53 |
| Control Quijote (humano, 1605) | 28.50 | 58.23 |
| **Control Wikipedia 2014 (humano, comparable)** | **10.35** | **16.24** |

### Cómo leerlo

Las dos variantes que bajaron en ZeroGPT subieron perplejidad y burstiness; la que
no bajó, no. Como señal **relativa** entre versiones del mismo texto, sirve.

Como meta absoluta, no: el texto humano del mismo registro es *más previsible* que el
ensayo generado y tiene menos de la mitad de burstiness que la variante 01. Estas métricas
reflejan lo que castigan los detectores, no cómo escribe una persona. El Quijote
parece «muy humano» por ser español de 1605, no por ser humano.

### El clasificador, desactivado por defecto

Con `--clasificador` se agrega P(IA) de
`bibbbu/multilingual-ai-human-detector_xlm-roberta-base`. Según su ficha, está afinado
en **inglés, chino y vietnamita**; el español queda fuera de su dominio. En el benchmark
dio 99.97% a las cuatro variantes y **99.96% al control humano de Wikipedia**: solo
distinguió el Quijote. No sirve para decidir nada en español; se conserva para poder
reproducir el benchmark.

Trampa de su mapeo de etiquetas: expone `LABEL_0`/`LABEL_1` sin nombre. Se fijó
`LABEL_1` = IA porque el Quijote cae en `LABEL_0` con 0.998. Un `argmax` sin validar
habría reportado el Quijote como IA. Siempre valida un mapeo así con un control.

## 7. Tabla resumen

| Instrumento | Requiere | ¿Sirve para decidir? |
|---|---|---|
| `verificar_fidelidad.py` | Python | **sí, bloqueante** |
| `estilo.py` | Python | sí, para comparar versiones y encontrar delatores |
| ZeroGPT | ego-browser | sí, el más estable de los web (el Quijote dio lo mismo en dos corridas) |
| GPTZero | ego-browser | **no fiable**: no reproducible y con falsos positivos |
| Grammarly | ego-browser + cuenta | útil si es el detector de quien pide el trabajo |
| `detect_local.py` perplejidad/burstiness | venv + torch | solo como señal relativa |
| `detect_local.py --clasificador` | venv + torch | **no**: fuera de dominio en español |

## 8. Solución de problemas

| Síntoma | Causa | Solución |
|---|---|---|
| El clic no arranca el escaneo | anuncio interstitial encima | eliminar overlays antes de hacer clic |
| «intercepts pointer events» en ego-browser | verificación de acción demasiado estricta | usar `mouse.click` por coordenadas, no `page.click(ref)` |
| El score sale `—%` | la espera se cumplió con el placeholder | exigir `[0-9]+%` y ausencia de `—%` |
| No aparece el veredicto | el resultado está en otra página | esperar una página nueva y leerla |
| Un porcentaje raro (30%, 98.4%) | es marketing o un descuento, no el score | anclar al bloque de resultado |
| El detector no responde tras varios escaneos | límite de uso gratuito por IP | esperar, cambiar de red, o iniciar sesión |
| `P(IA)` idéntico en todos los textos | el clasificador no está entrenado en español | no usarlo; ver §6 |
| ego-browser no lee el archivo | su proceso no hereda cwd ni entorno | los scripts ya pasan la ruta absoluta; si escribes uno propio, haz lo mismo |
| Todo sale marcado como IA, incluso el control humano | el detector tiene sesgo de registro | reportarlo; el problema es el detector |
